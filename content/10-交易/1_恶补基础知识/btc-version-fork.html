比特币 version 与软分叉

从 v1 一路到 Taproot，看 version 字段是怎么从「数字序号」变成「二进制标记位」的。

重点

软分叉 = 整条链仍然只有一条，只是部分矿工打包的区块带上新版 version／标志位；老节点依旧认可这条链，不会分裂。

version 演进路线

v1 → v4 → 位标记
v1
最早版本，没有额外 BIP 功能标记
时间范围：BIP34 之前
v2
规则：Coinbase 里必须写入区块高度
目的：防止预挖漏洞
v3
签名严格编码校验（DER）
修复脚本延展性漏洞
v4
增加 OP_CHECKLOCKTIMEVERIFY 锁定脚本
支持时间锁交易
bit
不再单纯递增数字，改用 bit 位标记功能
隔离见证：扩容、修复延展性
bit
Schnorr 签名 + Tapscript
隐私更好、脚本更灵活
⇄

同时存在：老版本区块

没升级的矿池依旧可以打出旧 version 区块
新旧区块共存于同一条主链
软分叉的核心特点

三种「分叉」不是一回事

看链的形状就懂了

软分叉 Soft Fork

规则变严

绿色 = 带新 version／标志位的区块，链不分裂

  • 规则变严，增加新校验
  • 老节点看不懂新功能，但认可区块合法
  • 只有一条主链，不会分裂成两个币
  • 区块 version／标志位改变，用来标记新功能

硬分叉 Hard Fork

规则不向后兼容

同一条链永久分成两条，两条互不承认

  • 规则不向后兼容
  • 新旧节点互不承认对方的区块
  • 链永久分裂，变成两种币（BTC / BCH）
  • 两条独立链，互不认同

挖矿临时分叉

孤立块 orphan

短暂两条，短的那条作废，交易回到 mempool

  • 几乎同时挖出两个区块
  • 短暂两条链，节点选工作量更大那条为主链
  • 短链作废，交易回 mempool
  • 和协议升级（软／硬分叉）完全无关

一句话回顾

version 不再只是简单数字序号（SegWit 之后），而是一组二进制标记位。软分叉激活后：一部分矿工打出带新标记的区块、一部分继续老版本区块，它们可以穿插在同一条链里面，链始终只有一条。老节点照常同步、验证 PoW，只是不会解析新脚本功能。
